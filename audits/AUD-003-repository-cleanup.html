4orm IQRepository auditAUD-003 · v1.028 October 2026Internal

A second copy of the application was being served to the public

An audit of the founders-code/4orm-IQ repository taken on 28 October 2026, before building the new landing page on top of it. The application code came out sound. The repository around it did not: it was publishing a stale duplicate of the whole engine, both investor decks and every internal document at public URLs, because Vercel deploys whatever is in the repository and nothing told it otherwise.

Worst exposure

The engine, twice

A folder holding an older snapshot of the whole application, including the Search Cue and the authentication code, was reachable from 4ormiq.com as plain text.

Second exposure

Everything else

Both decks, the UX plan, 92 build scripts, 12 internal reports and the change register were all downloadable from the live domain.

What was sound

The API layer

No hardcoded secrets. Every key read from the environment. Helpers correctly underscore-prefixed so Vercel never routes them. 30 modules, all parsing.

Near miss

Two files that were not duplicates

Two pairs matched on byte count and differed in content. Deleting on the byte count would have destroyed the newer of two control-room builds.

01

What was found sound, and should be said first

The instruction behind this audit was to look for spaghetti in the backend before building on it. It is not there, and saying so plainly matters more than the findings below, because the findings are all about the repository rather than the code.

CheckedResultState
Hardcoded credentialsNone. Scanned for API key, token, connection-string and private-key patterns across every JavaScript, JSON, SQL, HTML and Markdown file in the repository, including the duplicate tree.Clean
Secret handlingAll 17 configuration values read from process.env. No .env file was ever committed.Clean
Endpoint surface8 endpoints. The other 22 modules are underscore-prefixed, which is how Vercel is told not to route a file. The convention is applied consistently and is load bearing.Clean
SyntaxAll 30 API modules parse. 29 of 30 import cleanly; the one failure is @anthropic-ai/sdk not being installed in the audit environment, and it is declared in package.json.Clean
Internal linksEvery relative link in every served page resolves to a file that exists.Clean

The separation of concerns in api/ is real rather than decorative: the catalogue, the cue, the output contract, the budget, the recency window and the standing ranker are each one file with one job, and the comments in them explain reasoning rather than restating the code.

02

A stale copy of the whole application, at a public URL

A directory named 4orm-iq-site 3 held an earlier snapshot of the entire application: its own api/, its own index.html, its own vercel.json, its own test suite. The name is the shape of a third download from a browser, and it had been committed along with everything else in a single upload.

Vercel deploys the repository. A JavaScript file that is not under the project root api/ directory is not treated as a function, so it is served as a static asset. The Search Cue, the output contract and the authentication module were therefore readable, in full, by anyone who guessed the path.

Every file in it was superseded by a larger version at the root, which settles which copy was live and which was stale.

A .vercelignore now holds all of it off the deployment. Every file stays in version control; it simply stops being downloadable from the live domain. The deployed footprint falls from 26M to 11M. The seven screenshots were deleted outright, being the only items with no further use.

04

One number that disagreed with itself

Six places in the operations board, four in the evidence map and one on the landing screen print 135 registers. A comment in api/check.js explaining the empty-sweep guard printed 134.

The catalogue settles it, because the catalogue computes it rather than stating it:

export const TOTAL_SOURCES = CATALOGUE.filter(s => s.enabled).length;

152 entries, 17 disabled, 135 enabled. Run on 28 October 2026.

135 is correct and the comment was stale. Corrected. The severity is low because the figure sat in prose rather than in a code path, but it is recorded because a product whose first promise is that coverage is counted rather than asserted cannot afford a second number for the same thing anywhere in its own source.

05

The near miss, which is the finding worth keeping

Two pairs of files matched exactly on byte count and were queued for deletion as duplicates. A hash comparison run before the deletion showed both pairs differed.

PairWhat actually differed
preview-evidence.html
evidence.html		The older file says 121 registers against the live 135. Same length, different content.
preview-control-room.html
4orm-iq-controlroom.html		Build stamps 20260917.1811 and 20260911.0619. The file that looked like the throwaway preview was the newer of the two.

Both were moved to archive/ rather than deleted. The live control room is admin.html, stamped 20261001.0717, which is newer than either, so nothing stale is being served.

The rule this produces: file size is not identity. Two files of the same length are a reason to run a hash, never a reason to skip one.

The order of work
